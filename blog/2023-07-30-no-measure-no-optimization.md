前两天和几个大佬讨论了一些性能优化问题，交流了很多 “一通优化猛如虎，性能收益万分五” 的案例，综合思索下，这篇 blog 就产生了。



我看一些社区内的性能相关的文章，总会有这两大流派的身影：

- 一是**虚空索敌**，要不研究 for 循环的 4 种写法哪种性能更好，要不研究变量在堆上还是在栈上，写单片机的都没这么抠搜
- 二是**列表集合**，列了一堆性能优化的 todo list，每条看起来都有道理，点赞收藏一堆，但当自己真要实践时却发现有用的不多



这两大流派其实犯的错误都是一样的，前者是想通过一些**理论分析**指导性能，后者是想通过**经验总结**指导性能。但大家都知道刻舟求剑和照猫画虎是解决不了所有问题的，在性能优化这个方向上，最重要的还是 ***MEASURE, MEASURE, MEASURE***。



下面我举几个反常识的例子，讲讲测量和数据监控在性能优化中的重要性。





### 离线包就一定更快吗

在移动端 H5 性能优化的最佳实践中，离线包一定是座上宾。

离线包的原理也很简单，就是当网页发起网络请求时，移动端会拦截 Webview 的请求，然后重定向到已经下载好的本地资源上，这样就可以把平均 100-200ms 的 Network IO 转为 10-20 ms 的 File IO，大大优化资源请求耗时，提升首屏性能。

在 95% 的情况下，离线包确实可以大大提升整体的性能水位，但流量大了业务多了总能碰到几件不寻常的事情。



#### 线程池排队

之前帮助某业务排查问题时，开启离线包后，结果在 Android 上表现不尽人意，网络耗时并没有很大的提升。在 chrome devtools performance panel 上查看请求数据，发现各网络请求有个稳定的 Queue 时间。然后试图在纯前端修改定位问题，结果忙活一天也没什么进展。

后来灵光一现，觉得问题可能和前端问题不大，于是拉了客户端的 performance 数据。两份数据一对比才发现，由于这个业务进入时机较早，网络请求又全部托管给 Native，此时 Native 业务繁忙，线程池已经完全打满了，所以网页的网络请求都在后面排队呢，最后排队的时间大于了网络请求的时间，反而收益不是很大了。





#### 进程通信

说完 Android 再说说 iOS 的。

现在 iOS 使用的 WebView 只有 WKWebView 一种了，特点就是占用一个独立进程，不像 UIWebView 一样和 APP 主线程抢资源了，好处有很多，比如说整体的内存占用更低，大大降低 crash 概率，但在离线包这里却有可能会照成性能劣化。

劣化的主要原因就是跨进程通信成本。如果不做离线包，那所有的网络请求都在 WKWebView 进程的 network 线程进行调度，上下文切换会比较轻量；如果做了离线包，就会变为以下流程：

```
 WKWebView 发起网络请求 -> 主进程拦截请求并重新发起 -> 把资源回传给 WKWebView 进程
```

这里就存在两次跨进程通信，如果主进程繁忙，表象之一就又是 Queue 时间过程，最后会造成离线包劣化了性能。





#### code caching

前两个是 Native 相关的，这次再说一个 Webview 内核相关的。

这个案例是 @777 介绍给我的。上了离线包后，经过数据监控，他们一个项目直接劣化了。最后定位的原因也比较离奇，是浏览器内置的 code caching 缓存失效导致的。



首先介绍一下这个项目背景，项目只有两个 js bundle，但是 js bundle 特别大。按常理来说，bundle 越大，离线化优化的网络耗时就越多，那性能怎么反而劣化了？

其实在整个 script 的生命流程里，网络请求只是最前置的一节。浏览器下载好 JS 后，JS 引擎还存在着 parse，compile 和 evaluate 三个流程，一般来说，js bundle 越大，这三个流程就越长。

浏览器开发者也意识到这个问题，所以他们内部会对 js script 的 parse & compile 产物做缓存（即 code caching），大致的流程如下：

- 第一次访问，从网络上获取资源，并把资源源文件存储到磁盘上，即 disk cache，然后再执行 parse/compile/evaluate 3 个流程
- 第二次访问，从 disk cache 获取到源文件，并把 parse/compile 得到的 bytecode 文件做缓存
- 第三次访问，直接拿到 bytecode 使用，同时省去 network/parse/compile 3 个流程的耗时（有 AOT 的味道了）



 离线包劣化的原因就在于，开启离线拦截后就会破坏上面的步骤 1 和 2，这就导致 code caching 无法生成。此消彼长之下（尤其是网网速良好 js bundle 又比较大的场景），开启离线包后反而整体的性能劣化了。
