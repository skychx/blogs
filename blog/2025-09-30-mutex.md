## 初步实现

### 最小案例

我们先假设一个最简单的并发场景，有一个用于用户注册的类 UserRegistry，每次可以调用 register 注册一个新用户：

```typescript
const delay = (num: number) => new Promise((resolve) => setTimeout(resolve, num));

class UserRegistry {
  private users = new Set<string>();

  public async register(username: string): Promise<boolean> {
    if (this.users.has(username)) {
      return false;
    }

    await delay(Math.random() * 100); // 模拟其他的异步操作耗时
    this.users.add(username);

    return true;
  }
}
```

这个 register 函数实现上读写分离，而且有不确定的异步耗时，如果外界几乎同时注册一个名为 'Bob' 的用户，就会出现多个用户都注册成功，但是实际只有一个 user 注册的多对一情况：


```typescript
const center = new UserRegistry();

Promise.all([
  center.register('Bob'),
  center.register('Bob'),
  center.register('Bob'),
]).then((results) => {
  console.log(results); // 期望：[true, false, false]，但可能是 [true, true, true] 或其他
});
```

这种典型的竞态问题，核心就是 `register` 方法里的检查和插入不是原子的，再加上不同的 delay 耗时，导致检查插入**交错进行**从而引发了 BUG。

### 队列化处理

遇到这种问题的时候，其实一个自然而然的思路就是队列化处理。每次执行 register 的时候，并不会直接执行内部的 task，而是把这个 task 推到一个队列里去，然后依次执行这个队列里的代码。

## 其他语言中的互斥锁

我们就拿最简单一个案例说明一下。假设有个某个 Inc() 函数要对某个变量做操作，然后用随机 sleep 模拟这个操作的耗时。在 Go 语言里就是类似的伪代码：

```go
type Counter struct {
    mutex sync.Mutex
    value int
}
func (c *Counter) Inc() {
    c.mutex.Lock()
    defer c.mutex.Unlock()

    time.Sleep(time.Duration(rand.Intn(100)) * time.Millisecond)
    c.value++
}
```

可以看到在 Go 语言里主要的用法就是先实例化一个 Mutex，然后在 Inc() 执行前加锁，在 Inc() 执行完毕后释放锁。

Go 语法可能比较甜，我们再换个语言，比如说 Java，可以看到更多的调用细节：先在 Inc() 执行开始时加锁，等具体的逻辑执行完毕后，再在 finally 阶段释放锁：

```java
public class Counter {
  private final ReentrantLock mutex = new ReentrantLock();
  private int value = 0;

  public void Inc() {
    mutex.lock();
    try {
      Thread.sleep(new Random().nextInt(100));
      value++;
    } catch (InterruptedException e) {
      e.printStackTrace();
    } finally {
      mutex.unlock();
    }
  }
}
```

那么其实照猫画虎，把 Java 语言直接搬到 JavaScript 上，我们可以这样写：

```javascript
class Counter {
  private mutex = new Mutex();
  private value = 0;

  public async Inc() {
    mutex.lock();
    try {
      await sleep(Math.random() * 100);
      value++;
    } catch (e) {
      console.error(e)
    } finally {
      mutex.unlock();
    }
  }
}
```

但是呢，JavaScript 其实有个新的关键字，叫做 using，balabala，改造之后的 Mutex 语法可以变成这样：

```javascript
class Counter {
  private mutex = new Mutex();
  private value = 0;

  public async Inc() {
    using _ = mutex.lock();

    await sleep(Math.random() * 100);
    value++;
  }
}
```
